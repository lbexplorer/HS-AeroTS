\subsection{PX4 Software-Module Suspect Ranking}
\label{sec:module_ranking}

The architecture-aware layer maps topic-level SHAP evidence to commit-specific PX4 software-module inspection candidates. Its input is the topic-level evidence $E_{it}$ from Section~\ref{sec:shap_evidence} together with firmware provenance retained in each ULog header. The corpus contained seven firmware commits, and the most frequent commit, \texttt{\seqsplit{82aa24adfca29321cfd1209e287eab6c2b16780e}}, occurred in 562 of 1389 usable logs; its source tree was selected for static analysis. All architecture-aware aggregate results are recomputed only from matching-commit logs. In the fixed test partition, this restriction retains 14,419 of 34,059 windows (42.3\%) from 561 matching-commit logs and 1,393 of 3,602 ground-truth anomalous windows (38.7\%). Windows from the other six commits are excluded rather than propagated through a mismatched graph. The output of the matching step is therefore a firmware-coherent subset of windows, not a prediction for logs from an unmatched revision.

For the selected commit, the source scanner searches the configured PX4 C/C++ source globs for \texttt{ORB\_ID(topic)} occurrences, assigns publisher or subscriber roles using the nearest recognized uORB API hint within a 500-character local context, and converts source paths into module identifiers. These records define a static graph $G=(\mathcal{T},\mathcal{M},\mathcal{E})$, where $\mathcal{T}$ is the set of evaluated topics, $\mathcal{M}$ is the set of source-tree modules, and $\mathcal{E}$ contains topic--role--module records; the propagation mode $r$ selects a subset or interpretation of this fixed edge set. An internal consistency check covers all 244 unambiguous same-statement declarations or calls involving the 18 evaluated topics. Within this explicit scope, agreement with the statement-level role rule and recovery of its explicit edges are both 1.000. This is not an independent gold audit because the reference and parser use the same uORB hint vocabulary at different context granularities; it does not quantify recall for macro-generated, indirect, conditionally compiled, or runtime-created relations.

The initial source-tree scan contains 180 edges and 54 modules. A conservative-exclusion sensitivity removes paths containing examples, templates, tests, POSIX, QURT, Bebop, Linux, Snapdragon, simulator, or replay markers for the log-confirmed PX4FMU\_V2 and NuttX environment. The filtered edge list must be a strict subset of the original graph and is checked for evidence conservation. This rule is deliberately path-based: neither the unfiltered nor filtered graph is an actual target-specific compiled build graph. Full exclusion rules and software settings are listed in Appendix~\ref{app:reproducibility}. The graph is consequently a static source-tree representation of topic connectivity, not a compiled or runtime execution graph.

For propagation mode $r$, let $\mathcal{M}_t^{(r)}\subseteq\mathcal{M}$ be the modules connected to topic $t$ and $E_{it}$ the topic-level evidence for window $i$. Evidence is allocated uniformly across the connected modules:

\[
A_{it,m}^{(r)}=\begin{cases}
E_{it}/|\mathcal{M}_t^{(r)}|,&m\in\mathcal{M}_t^{(r)},\\
0,&\text{otherwise},
\end{cases}
\qquad
S_{i,m}^{(r)}=\sum_t A_{it,m}^{(r)}.
\]

Here, $A_{it,m}^{(r)}$ is the share of topic $t$'s evidence assigned to module $m$ for window $i$, and $S_{i,m}^{(r)}$ is the resulting module suspect score before ranking. The uniform allocation preserves each topic's evidence mass within a propagation mode, while the number of connected modules determines how concentrated or diluted that topic's contribution becomes.

The static SHAP analysis evaluates producer-only, consumer-only, and bidirectional propagation. A sensitivity divides each module's aggregate score by its number of mapped topics before renormalization, exposing dependence on graph degree. Scores can be retained per window or aggregated over the stated matching-commit set; this aggregation does not identify a known defective module in real flights. The paired-replay extension below reuses the publisher relations but supplies residual evidence instead of TreeSHAP evidence, and retains the full 54-module candidate universe. It does not apply the 36-module real-flight exclusion sensitivity to improve replay ranks. Mapping coverage, conservation, and real-flight propagation sensitivity are reported in Section~\ref{sec:shap_module_results}.
