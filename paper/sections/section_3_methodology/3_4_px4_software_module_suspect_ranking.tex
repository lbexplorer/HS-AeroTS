\subsection{PX4 Software-Module Suspect Ranking}

The architecture-aware layer maps topic-level SHAP evidence to commit-specific PX4 software-module suspects. Firmware provenance was read from ULog headers. The corpus contained seven firmware commits, and the most frequent commit, \texttt{82aa24adfca29321cfd1209e287eab6c2b16780e}, occurred in 562 of 1389 usable logs; its source tree was selected for static analysis. All architecture-aware aggregate results are recomputed only from matching-commit logs. In the fixed test partition, this restriction retains 14,419 of 34,059 windows (42.3\%) and 1,393 of 3,602 anomalous Stage-2 windows (38.7\%). Windows from the other six commits are excluded from module aggregation rather than propagated through a mismatched graph.

The source scanner identifies uORB topic occurrences, assigns publisher or subscriber roles using the nearest recognized uORB API hint within a 500-character local context, and converts source paths into module identifiers. A source-grounded audit covers all 244 unambiguous same-statement declarations or calls involving the 18 evaluated topics. Within this explicit scope, parser-role agreement and explicit-edge recall are both 1.000. This audit does not quantify recall for macro-generated, indirect, or runtime-created relations. The graph is therefore a validated approximation for explicit uORB declarations at the selected commit, not a runtime execution trace.

For propagation mode $r$, let $\mathcal{M}_t^{(r)}$ be the modules connected to topic $t$ and $E_t$ its topic-level evidence. Evidence is allocated uniformly across the connected modules:

\[
A_{t,m}^{(r)}=\begin{cases}
E_t/|\mathcal{M}_t^{(r)}|,&m\in\mathcal{M}_t^{(r)},\\
0,&\text{otherwise},
\end{cases}
\qquad
S_m^{(r)}=\sum_t A_{t,m}^{(r)}.
\]

Producer-only, consumer-only, bidirectional, topic-only, and random-mapping modes represent different engineering interpretations or controls for the same topic evidence. Uniform allocation can favor or dilute modules as a function of topic degree. A further sensitivity divides each module's aggregate score by its number of mapped topics before renormalization. These ablations are reported rather than treating one propagation rule as uniquely valid. The resulting ranking is architecture-aware diagnostic evidence and a software-module suspect ranking. It is version-dependent and static; it is not root-cause localization. Mapping coverage, edge counts, module counts, empirical conservation, and propagation-mode results are reported in Section 5.2.
