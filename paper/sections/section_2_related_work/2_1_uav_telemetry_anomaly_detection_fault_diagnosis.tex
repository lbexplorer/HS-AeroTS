\subsection{UAV Telemetry Anomaly Detection and Fault Diagnosis}

UAV telemetry fault detection and diagnosis combines system-specific flight knowledge with multivariate time-series analysis. Surveys distinguish model-based, signal-based, knowledge-based, and data-driven approaches, while also noting that real-flight evidence is less abundant than simulation or laboratory validation \cite{fourlas2021survey,puchalski2022uav,adaika2025fdd}. Flight logs record coupled state estimates, estimator innovations, inertial measurements, actuator responses, power variables, and system-health indicators; an abnormal condition may therefore appear across several channels rather than as an isolated sensor excursion. Keipour et al. developed an online detector for autonomous aerial vehicles and released ALFA as a real-flight fault and anomaly dataset \cite{keipour2019automatic,keipour2021alfa}. More recently, UAV-SEAD organized real PX4 logs around state-estimation-related runtime anomalies in External Position, Global Position, Altitude, and Mechanical/Electrical domains \cite{kabaoglu2026uavsead}. These datasets make windowed multi-source telemetry a practical basis for both anomaly detection and fault-domain diagnosis, but their labels, channel availability, and operating conditions remain dataset-specific.

General multivariate time-series anomaly detection provides several complementary modeling paradigms for such data. Isolation Forest detects sparse deviations through random partitioning without explicitly modeling temporal order \cite{liu2008isolation}. Reconstruction and probabilistic sequence models instead learn normal temporal or inter-channel structure, as illustrated by MSCRED and OmniAnomaly \cite{zhang2019mscred,su2019omnianomaly}. Graph-based methods such as GDN learn dependencies among sensors, whereas TranAD and Anomaly Transformer use attention to represent longer temporal relationships \cite{deng2021gdn,tuli2022tranad,xu2022anomaly}. Recent methods further model cross-channel structure through frequency-domain patching in CATCH or a Granger-causality perspective in GCAD \cite{wu2025catch,liu2025gcad}. These methods broaden the available baselines for multi-source flight data, but their primary output is still an anomaly score or binary decision. They do not inherently map a detected window to the UAV-specific fault domains used for engineering diagnosis, nor do they establish a traceable relationship between an influential signal and the flight-control software architecture.

For real UAV telemetry, AeroTSBoost is the closest detector-level reference because it represents fixed-length flight windows with temporal-statistical descriptors and applies gradient-boosted trees to anomaly mining \cite{wei2026aerotsboost}. Its use of compact descriptors and LightGBM \cite{ke2017lightgbm} provides a reproducible alternative to sequence models when the channel set is heterogeneous and the data are strongly imbalanced. The present study therefore uses an AeroTSBoost-compatible Stage 1 protocol for binary runtime anomaly detection, while treating binary detection as only the entry point to diagnosis. Stage 2 conditionally assigns detected anomalous windows to one of the four UAV-SEAD fault domains, and a Direct Five-Class model is retained as a non-cascaded comparator. This design separates the question of whether a window is abnormal from the question of which fault domain best explains the labeled runtime condition.

Evaluation choices are particularly consequential for imbalanced, overlapping telemetry windows. Accuracy and AUROC can remain high when normal windows dominate, whereas precision--recall analysis exposes the trade-off on the minority anomaly class \cite{davis2006relationship,saito2015precision}. Accordingly, AUPRC is emphasized for binary detection, while Macro-F1, Balanced Accuracy, and per-class Recall are used for fault-domain diagnosis so that minority domains cannot be hidden by aggregate accuracy. Time-series evaluation must also account for temporal range labels and partition dependence \cite{tatbul2018precision,wenig2022timeeval}. Randomly assigning overlapping windows can place nearly identical samples, or samples from the same flight log, in both training and test sets; broader benchmark analyses have shown that such evaluation choices can create optimistic conclusions \cite{wu2023benchmarks}. The experiments in this study therefore report fixed chronological results together with purged and leave-log-out protocols, and treat ALFA only as a zero-shot binary reference because its label space does not support direct four-domain transfer.
